# PreToolUse Comment Yap Advisory

Supported hosts: all

`hooks/advisory-nudge/comment-yap-advisory/impl.py` nudges the agent to
re-examine a comment block that is **long and unanchored** — the shape named
`yap`: a comment that says a great deal and informs about nothing. Advisory
only; it writes to stderr and exits 0.

## Why this exists (issue #1141)

A reasoning model fills its context with detail to predict better. The defect
is that the monologue does not stay inside the model — it leaks into the
generated code as comments. The residue has three recognizable shapes: a
30-line comment above a simple type, a 200-line explanation crammed above one
function, and 50 lines at the top of a file that explain nothing identifiable.

Nothing else in the toolchain catches it. A wrong type fails to run; a wrong
comment runs fine forever. Tests pass, types check, lint passes, CI is green,
and the only thing that notices is a human reading the diff. The failure also
happens at **authoring time**, where a memory rule about comment discipline is
not retrieved — the same argument that promoted
[`secret-print-redaction-advisory`](../secret-print-redaction-advisory/spec.md)
from memo to hook.

**Provenance differs from the usual promotion, and is stated rather than
implied.** Praxis hooks are normally promoted after ≥5 measured recurrences in
this repo's fire ledger. This one adopts an external convention instead, so it
ships advisory-only and is scored on the same evidence basis as every other
hook by [`docs/hook-prune-audit.md`](../../../docs/hook-prune-audit.md).

## The design problem: length is not the signal

This repo is its own counterexample. The sibling
`secret-print-redaction-advisory/impl.py` opens with a **68-line module
docstring**, and it is one of the most useful things in the file. A hook that
fires on it is wrong, and would be pruned within one audit cycle.

What separates it from yap is not length but **anchoring**. A comment that
earns its length cites something checkable — an issue, a URL, a path, an
identifier, a flag, an example, a measured figure. Yap narrates. That property
is structural and cheap to count, so the hook never has to have taste: it
reports the shape and hands the five questions back to the author.

## Trigger criteria (2-signal AND gate)

A comment run must be **both** long **and** unanchored. Either signal alone is
silent.

| Detector | Trigger | Shape it names |
| ---------- | --------- | ---------------- |
| **D1 · disproportionate preamble** | run ≥ `PRAXIS_YAP_PREAMBLE_LINES` (12) lines, attached (no blank line) to a code span of ≤ 3 lines, with < 2 anchors | *30-line comment above a simple type* |
| **D2 · unanchored sprawl** | run ≥ `PRAXIS_YAP_SPRAWL_LINES` (25) lines whose anchor count is below 1 per 10 comment lines | *200-line function preamble*; *50-line file header* |

The file-header case needs no third detector — it is D2 evaluated at offset 0.

**Subject span** (D1) is the count of consecutive non-blank, non-comment lines
immediately following the run, stopped at the first blank line, the next
comment, or EOF. A type alias or a one-line constant gives 1–2; a real
function body's first paragraph runs past the threshold.

**Anchors** — any one occurrence in a comment line:

| Anchor | Example |
| -------- | --------- |
| issue / PR reference | `#1141` |
| URL | `https://…` |
| backticked span | `` `safe_tokenize` `` |
| path-like token | `hooks/_lib/_hook_utils.py`, `hooks/_lib/` |
| code fence or doctest | ` ``` `, `>>>` |
| quoted literal (paired double quotes, straight or typographic) | `"session end"` |
| flag or placeholder | `--body-file`, `<name>` |
| structured API section | `Args:` `Returns:` `Raises:` `@param` `:rtype` |
| table row | a line with ≥ 2 `\|` |
| measured figure | `6+ times`, `22.6 ms`, `80%` |

Single-quoted spans are deliberately **not** anchors: an apostrophe pair spans
ordinary prose too readily to mean anything.

## Exclusions (silent — no advisory)

- **Unmapped file extension** → return 0 before any scanning. Comment syntax
  is resolved from the extension, never guessed. This is also what excludes
  prose files (`.md`, `.txt`, `.rst`, …), where every line is "comment" and
  the hook would otherwise fire on any document — including this spec.
- **License / SPDX headers** — `Copyright`, `SPDX-License-Identifier`,
  `Licensed under`. Legally required, structurally unanchored, nobody's
  monologue.
- **Generated-file markers** — `@generated`, `Code generated by`,
  `DO NOT EDIT`.
- **Commented-out code** — a run whose lines are ≥ 60% code-shaped. Dead code
  in comments is a real problem but a different one; firing the yap advisory
  on it would mislabel it.
- **Trailing comments** — a marker must be the first non-whitespace token on
  its line to join a run. Yap is block-shaped, and the rule sidesteps nearly
  every string-literal false positive without a lexer.
- **Docstrings, for D1 only** — a docstring documents its enclosing function,
  not the two statements that happen to precede the first blank line, so the
  measured span says nothing about proportion. D2 still applies.

## Languages

Comment syntax is keyed by extension:

| Syntax | Extensions |
| -------- | ------------ |
| `#` + docstrings | `py` `pyi` |
| `#` | `sh` `bash` `zsh` `rb` `pl` `pm` `yaml` `yml` `toml` `tf` `tfvars` `nix` `jl` `r` `ex` `exs` |
| `//` + `/* */` | `c` `h` `cc` `cpp` `cxx` `hpp` `hh` `java` `go` `rs` `js` `jsx` `mjs` `cjs` `ts` `tsx` `swift` `kt` `kts` `scala` `php` `cs` `dart` `m` `mm` `proto` `groovy` `gradle` `scss` `less` |
| `/* */` only | `css` |
| `--` | `sql` `lua` `hs` `elm` |

## Parsing guarantees and their limits

The scanner is line-oriented with a small state machine, not a lexer. Three
cases are handled explicitly because getting them wrong fabricates a finding
rather than missing one — each is pinned by a test:

- **A multi-line string opener** (`MSG = """\`) is tracked, so the bare
  delimiter that closes it is not read as a docstring opener that would then
  score the rest of the file as one enormous comment run. The opener's line
  shape is unconstrained: a trailing backslash continuation is as common as a
  bare one.
- **A delimiter nested inside the other quote style** (a table of delimiters
  such as `('"""', "'''")`) is skipped rather than counted. Counting it
  desynchronizes the scan for the remainder of the file.
- **A triple quote following a line that ends mid-expression** (`(`, `[`, `,`,
  `=`, `+`) is an operand — test fixture data, a `write_text(` argument — and
  opens a string, never a comment run.

Known limit, stated rather than hidden: a line beginning with a comment marker
*inside* a multi-line string in a language without tracked docstrings can still
be read as a comment. The volume thresholds and the anchor rule make this a
narrow tail, and the code-shape exclusion covers most of what remains.

## Response

Advisory only. stderr, exit 0, no JSON decision, never blocks. At most
3 findings (`_ADVISORY_LIMIT`, matching sibling convention). The text does not
say "shorten this" — it prints the five questions the word `yap` stands in for:

1. What value does this comment actually provide?
2. What is not already clear from the code itself?
3. What does a future reader not need?
4. Is the explanation next to the code it explains?
5. Is a comment needed here at all?

## State and concurrency

Stateless. No session file, no cache, no lock — the four questions in
[`DESIGN.md` § Session-state concurrency](../../../DESIGN.md#session-state-concurrency)
do not apply because there is no state to lose.

## Cost

The hook runs on every `Write` and `Edit`, so the budget is a design
constraint:

- **Fast reject** — unmapped extension, empty text, or an over-cap payload
  returns before any line work.
- **Hard byte cap** — `PRAXIS_YAP_MAX_BYTES` (256 KiB). A larger payload
  returns 0 rather than being partially scanned; a partial scan would be a
  verdict about a fragment.
- **Single forward pass**, no whole-text regex, all patterns precompiled at
  import.
- **No line list** — lines are yielded by a `str.find("\n")` generator instead
  of `splitlines()`, so auxiliary memory is O(longest line), not O(file).
- **O(1) run state** — counters (`lines`, `anchors`, `code_shaped`) plus one
  100-char snippet. The run's text is never accumulated.
- **Bounded work** — a run stops accumulating at 4096 lines, and anchor
  counting stops once no reachable run length could still fire D2. All of a
  run's counters freeze together at the cap: advancing `code_shaped` past a
  frozen `lines` would drive the code-shape share above 1.0 and suppress the
  run on arithmetic rather than on what it contains.

Not a member of the `(PreToolUse, Bash)` dispatch group (ADR-0002), which is
Bash-only, so this is a **standalone** hook and applies `@fail_open` to
`main()` directly — the invariant rule 15 in
`scripts/check-plugin-manifests.py` enforces.

## Fail-open contract

- malformed JSON stdin → exit 0
- non-dict payload, tool other than `Write`/`Edit`, non-dict `tool_input` → exit 0
- missing/empty `file_path`, unmapped extension, empty content → exit 0
- unparseable env override → falls back to the default, never disables the hook
- any uncaught exception → `@fail_open` swallows it, exit 0

## Tunables

| Env | Default | Meaning |
| ----- | --------- | --------- |
| `PRAXIS_YAP_PREAMBLE_LINES` | `12` | D1 run threshold |
| `PRAXIS_YAP_SPRAWL_LINES` | `25` | D2 run threshold |
| `PRAXIS_YAP_MAX_BYTES` | `262144` | fast-reject size cap |

Thresholds only. Deliberately no mode switch and no `:ack` bypass marker — an
advisory that already exits 0 has nothing to bypass, and every extra knob is
surface the next prune audit has to score.

## Non-goals

- **No blocking mode.** ETHOS places *code patterns* under Convention, but
  comment prose sits close enough to taste that a deny would stop real work
  over style. Promotion would be a separate issue, with fire-ledger precision
  attached.
- **No LLM call, no semantic judgment.** The source argument is that a second
  model is not a trustworthy reviewer of the first; a hook that asked a model
  whether a comment is valuable would reproduce exactly the failure being
  described. This hook measures structure and hands the judgment back.
- **No commented-out-code detector**, **no stale-comment detector.** Both are
  real and both are separate hooks (SRP).
